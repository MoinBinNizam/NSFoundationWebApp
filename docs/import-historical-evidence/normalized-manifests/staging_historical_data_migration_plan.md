### ১. প্রোডাকশনে গেলে কি এই স্টেজিং ডাটা ডাটাবেজে থাকবে (Persist করবে)?

### ২. প্রোডাকশনে রিয়েল ক্যালকুলেশনের জন্য এই হিস্টোরিকাল ডাটা কীভাবে নেওয়া হবে?

প্রোডাকশন সার্ভারে এই হিস্টোরিকাল ডাটা নিয়ে যাওয়ার জন্য **২টি অত্যন্ত সহজ ও সম্পূর্ণ নিরাপদ উপায়** রয়েছে:

#### উপায় ১: এক কমান্ডে অটোমেটিক প্রোডাকশন স্টেজিং (সর্বোত্তম পদ্ধতি)
প্রোডাকশন সার্ভার যখন সেটআপ করবেন, প্রোডাকশন সার্ভারের `.env` ফাইলে প্রোডাকশন ডাটাবেজের লিংক (`MONGODB_URI`) থাকবে। এরপর ব্যাকএন্ড ফোল্ডারে একটি মাইগ্রেশন স্ক্রিপ্ট চালালেই:
```bash
# প্রোডাকশন ডাটাবেজে সব হিস্টোরিকাল পেমেন্ট ও ইনভেস্টমেন্ট রিয়েল ডাটাবেজে যুক্ত হয়ে যাবে:
npm run stage:all-historical
```
মাত্র কয়েক সেকেন্ডে জানুয়ারি ২০২৪ থেকে এপ্রিল ২০২৫ পর্যন্ত:
- ৩৬৭টি যাচাইকৃত আসল সদস্য পেমেন্ট (৳৪,৮৬,৭৭৫)
- ২০২৪ সালের বার্ষিক সদস্য শেয়ার ও হিসাব
- হিসাবরক্ষকদের ব্যাংক/বিকাশ/নগদ ব্যালেন্স
- ১৯টি ইনভেস্টমেন্ট প্রজেক্ট (১২টি পরিপক্ব এবং ৭টি রানিং)
সরাসরি প্রোডাকশন ডাটাবেজে নির্ভুলভাবে সংরক্ষিত হয়ে যাবে।

#### উপায় ২: ডাটাবেজ ব্যাকআপ ও রিস্টোর (`mongodump` & `mongorestore`)
লোকাল ডাটাবেজের একটি স্ন্যাপশট নিয়ে প্রোডাকশন সার্ভারে আপলোড করা:
```bash
# লোকাল থেকে ব্যাকআপ নেওয়া
mongodump --db ns_foundation_db --out ./backup

# প্রোডাকশনে রিস্টোর করা
mongorestore --uri="your_production_mongodb_uri" ./backup/ns_foundation_db
```

### ৩. এই হিস্টোরিকাল ডাটা লাইভ সিস্টেমে রিয়েল ক্যালকুলেশনে কীভাবে ভূমিকা রাখবে?
